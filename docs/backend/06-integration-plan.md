# 06. План подключения API — по шагам

Приложение уже готово к бэкенду: все экраны авторизации, профиля и
уведомлений ходят через слой API (`src/api/` в мобильном приложении).
Пока бэкенда нет, каждый раздел работает на тестовых данных внутри
приложения. Когда раздел готов на сервере, мы включаем его одним
переключателем, без переделки экранов.

Поэтому делать и сдавать можно **по разделам**, в любом порядке. Ниже —
что входит в каждый раздел и как мы проверяем.

## Как приложение подключается

- Адрес: debug-сборки → **staging**, релизные → **prod**. Нужны оба
  адреса (сейчас в приложении заглушки `staging-api.travelgo.app` и
  `api.travelgo.app`).
- Заголовки каждого запроса:
  - `Accept: application/json`;
  - `Accept-Language: uk` (язык интерфейса: `uk`, `en`, `de`, `es`, `fr`);
  - `Authorization: Bearer <accessToken>` (если вошли).
- Тайм-аут запроса — 15 секунд.
- `401` → приложение один раз вызывает `POST /auth/refresh` и повторяет
  запрос. Если refresh не прошёл — выход на экран входа.
- Ошибки — строго формат из [00-api-guidelines.md](00-api-guidelines.md):
  приложение показывает текст **по `code`**. Неизвестный код — общий
  текст «Что-то пошло не так».
- Фото отправляется как `multipart/form-data`.

## Разделы

### 1. Авторизация (`auth`)

Документ: [01-auth.md](01-auth.md) — разделы «Регистрация», «Вход»,
«Восстановление пароля».

| Метод | Экран в приложении |
|---|---|
| `POST /auth/register/start` | Регистрация → «Зарегистрироваться» |
| `POST /auth/register/verify` | Ввод SMS-кода после регистрации |
| `POST /auth/code/resend` | «Отправить код повторно» (все сценарии) |
| `POST /auth/login` | Вход |
| `POST /auth/refresh` | Незаметно для пользователя |
| `POST /auth/logout` | Профиль → «Выйти» |
| `POST /auth/password/forgot` | «Забыли пароль?» → «Отправить код» |
| `POST /auth/password/verify` | Ввод SMS-кода при восстановлении |
| `POST /auth/password/reset` | «Новый пароль» → «Сохранить» |

Ответы на вход и подтверждение регистрации — `{ accessToken,
refreshToken, user }`, где `user` — как `GET /me`.

### 2. Профиль (`profile`)

Документ: [01-auth.md](01-auth.md) — раздел «Профиль».

| Метод | Экран |
|---|---|
| `GET /me` | При запуске приложения (если уже вошли) |
| `PATCH /me` | «Личные данные» → «Сохранить изменения» |
| `POST /me/password/verify` | Смена номера, шаг 1 (пароль) |
| `POST /me/phone/start` | Смена номера, шаг 2 → «Получить код» |
| `POST /me/phone/verify` | Ввод SMS-кода для нового номера |
| `POST /me/password` | «Смена пароля» |
| `DELETE /me` | Удаление аккаунта (экран сделаем, когда будет API) |

### 3. Фото профиля (`avatar`)

Документ: [01-auth.md](01-auth.md) — «Фото профиля».

| Метод | Экран |
|---|---|
| `POST /me/avatar` | Профиль → аватар / камера → «Выбрать из галереи» или «Сделать фото» |
| `DELETE /me/avatar` | Там же → «Удалить фото» |

### 4. Уведомления (`notifications`)

Документ: [05-notifications.md](05-notifications.md).

| Метод | Экран |
|---|---|
| `GET /me/notifications` | Список уведомлений, при запуске |
| `GET /me/notification-settings` | Настройки уведомлений |
| `POST /me/notifications/{id}/read` | Нажатие на уведомление |
| `POST /me/notifications/read-all` | «Прочитать всё» |
| `PATCH /me/notification-settings` | Переключатели |

Push (`POST /me/devices`) — отдельным шагом: в приложении для этого
нужно подключить Firebase.

### 5. Контент: маршруты, города, гиды (`content`)

Документы: [02-content-model.md](02-content-model.md),
[03-mobile-content-api.md](03-mobile-content-api.md),
[04-admin-api.md](04-admin-api.md).

Это самый большой раздел. В приложении он ещё на встроенных данных
(15 маршрутов, 6 городов, гиды) — переключатель и слой API для него мы
добавим, когда будет готова хотя бы `GET /routes` и `GET /routes/{id}`.
Начать стоит с админки: без неё некому наполнять маршруты.

## Рекомендуемый порядок

1. **Авторизация + `GET /me`** — без них остальное не проверить.
2. **Профиль** и **фото** — небольшие, быстро закрываются.
3. **Админка контента** (страны → города → места → маршруты) и
   импорт тестовых маршрутов из приложения.
4. **Контент для приложения** (маршруты, поиск, гиды, сохранённые).
5. **Уведомления** (список и настройки), затем **push**.
6. Подписка PRO через App Store / Google Play.

## Как сдаём раздел

1. Раздел работает на **staging**, есть тестовый пользователь
   (`+380978670317` / `123456789`, SMS-код `1610`, без реальной SMS).
2. Описание в `openapi.yaml` совпадает с документами (или документы
   обновлены — тогда сообщите, что изменилось).
3. Мы включаем раздел в приложении, проходим все сценарии на iPhone и
   Android, присылаем список замечаний (запрос, ответ, что ожидали).
4. Нет замечаний — раздел подключён.

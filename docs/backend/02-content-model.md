# 02. Модель данных: страны, города, места, маршруты, гиды

Общая модель контента. Её читает мобильное приложение
([03-mobile-content-api.md](03-mobile-content-api.md)) и наполняет
админка ([04-admin-api.md](04-admin-api.md)).

## Как устроено

```
Страна ─┬─ Город ─┬─ Место (точка на карте)
        │         │
        │         └─ Маршрут ── упорядоченный список мест (остановки)
        │                 │
        │                 └─ Автор: TravelGo | гид | пользователь
        └─ …
Гид ── его маршруты
```

- **Место** принадлежит городу и может входить в несколько маршрутов
  (Эйфелева башня — в «Классическом Париже» и в «Историческом Париже»).
  Создаём один раз, используем много раз.
- **Маршрут** принадлежит одному городу. Остановки — места этого города
  в нужном порядке.

## Переводы (`Localized`)

Любой текст для пользователя хранится на 5 языках:

```json
{ "uk": "Класичний Париж", "en": "Classic Paris", "de": null, "es": null, "fr": null }
```

- `en` — **обязателен** (запасной язык).
- `uk` — обязателен для публикации (основная аудитория).
- Остальные — по мере перевода. Если нет — показываем `en`.

Хранить можно JSONB-полем или отдельной таблицей переводов — на выбор
бэкенда, лишь бы API отдавал в описанном виде.

## Страна — `Country`

| Поле | Тип | Описание |
|---|---|---|
| `code` | `string` | ISO 3166-1 alpha-2: `UA`, `FR`. Ключ |
| `name` | `Localized` | «Франція», «France» |
| `isPublished` | `boolean` | Видна ли в приложении |
| `sortOrder` | `number` | Порядок в списках (меньше — выше) |

Список стран можно заполнить заранее (все ~250), публиковать — по мере
появления маршрутов.

## Город — `City`

| Поле | Тип | Описание |
|---|---|---|
| `id` | `uuid` | |
| `countryCode` | `string` | Страна |
| `name` | `Localized` | «Париж», «Paris» |
| `latitude`, `longitude` | `number` | Центр города (для карты) |
| `timeZone` | `string` | IANA: `Europe/Paris`. Нужен, чтобы «Открыто / Закрыто» считалось по местному времени |
| `coverImage` | `string` | URL обложки |
| `isPublished` | `boolean` | |

## Место — `Place`

| Поле | Тип | Описание |
|---|---|---|
| `id` | `uuid` | |
| `cityId` | `uuid` | Город |
| `name` | `Localized` | «Ейфелева вежа» |
| `description` | `Localized` | Коротко, 1 предложение |
| `address` | `string` | Адрес как есть, на местном языке |
| `latitude`, `longitude` | `number` | Точка на карте |
| `hours` | `OpeningHours \| null` | Часы работы (ниже) |
| `images` | `string[]` | Фото (первое — главное) |
| `wiki` | `string \| null` | Статья Википедии: `Eiffel_Tower` или `uk:Ейфелева_вежа` (сейчас приложение берёт оттуда фото, если своих нет) |

### Часы работы — `OpeningHours`

Как в приложении сейчас:

```json
"always"                                              // круглосуточно: площадь, улица, парк
{ "open": "09:30", "close": "23:45" }                 // каждый день
{ "open": "09:00", "close": "18:00", "closedOn": [1] } // выходной в понедельник
```

`closedOn` — дни недели: `0` — воскресенье … `6` — суббота. Время —
местное (часовой пояс города).

> Позже можно перейти на разные часы по дням недели, но для старта этого
> хватает.

## Маршрут — `Route`

| Поле | Тип | Описание |
|---|---|---|
| `id` | `uuid` | |
| `cityId` | `uuid` | Город (страна — через город) |
| `source` | `object` | Автор: `{ "kind": "travelgo" }`, `{ "kind": "guide", "guideId": "…" }` или `{ "kind": "user", "userId": "…" }` |
| `title` | `Localized` | «Класичний Париж» |
| `description` | `Localized` | Короткое, 1–2 предложения (для карточки) |
| `about` | `Localized[]` | Полное описание — абзацы |
| `coverImage` | `string` | Обложка |
| `durationMinutes` | `number` | Сколько идти вместе с осмотром |
| `distanceKm` | `number` | Длина пешком |
| `badge` | `string \| null` | Метка на карточке (ниже) |
| `stops` | `RouteStop[]` | Остановки по порядку |
| `status` | `string` | `draft` → `pending_review` → `published` / `rejected`, `archived` |
| `publishedAt` | `datetime \| null` | |

Считает сервер (руками не вводятся):

| Поле | Описание |
|---|---|
| `placesCount` | Число остановок |
| `rating` | Средняя оценка 1–5 по отзывам |
| `reviewsCount` | Число отзывов |
| `usedCount` | Сколько раз маршрут прошли |
| `travelersCount` | Сколько разных людей прошли |
| `travelers` | 3–5 аватарок прошедших (для карточки) |

### Остановка маршрута — `RouteStop`

| Поле | Тип | Описание |
|---|---|---|
| `placeId` | `uuid` | Место (из того же города) |
| `position` | `number` | Порядок: 1, 2, 3… |
| `visitMinutes` | `number` | Сколько времени заложено на место |
| `note` | `Localized \| null` | Необязательный текст именно для этого маршрута |

### Метки — `badge`

| Значение | На карточке | Кто ставит |
|---|---|---|
| `popular` | Популярный | Сервер, автоматически (много прохождений и сохранений) |
| `new` | Новий | Сервер, первые 14 дней после публикации |
| `guide` | Від гіда | Сервер, если автор — гид |
| `editorsChoice` | Вибір редакції | Админка |
| `family` | Для всієї сім'ї | Админка |
| `hiddenGem` | Прихована перлина | Админка |

На карточке показывается одна метка. Если подходят несколько — ручная
(из админки) важнее автоматической.

### Авторы маршрутов

- `travelgo` — маршруты нашей команды, созданные в админке. Попадают в
  «Рекомендовано» и «Популярні».
- `guide` — маршрут гида (гид позже будет заполнять свой кабинет; пока
  создаём за него в админке).
- `user` — маршрут пользователя. Публикуется только после проверки в
  админке. Автора в приложении не показываем.

## Гид — `Guide`

| Поле | Тип | Описание |
|---|---|---|
| `id` | `uuid` | |
| `name` | `Localized` | Имя |
| `title` | `Localized` | «Гід по Парижу» |
| `bio` | `Localized[]` | О себе — абзацы |
| `photo`, `cover` | `string` | Фото и обложка |
| `verified` | `boolean` | Проверен нами (галочка) |
| `cityIds` | `uuid[]` | Где водит |
| `contacts` | `object` | `phone`, `instagram`, `facebook: { name, url }`, `website` — всё необязательно |

Считает сервер: `rating`, `reviewsCount`, `usedCount` (сколько раз прошли
его маршруты), `online` (был в сети недавно — когда появится кабинет гида).

## Сохранённые маршруты

Сейчас хранятся только на телефоне. С бэкендом — таблица
`saved_routes (userId, routeId, savedAt)`, чтобы закладки не пропадали
при смене телефона.

## Отзывы и прохождения (позже)

Для `rating`, `usedCount` и меток понадобятся таблицы отзывов
(`userId`, `routeId`, `rating`, `text`) и прохождений (`userId`,
`routeId`, `startedAt`, `finishedAt`). API для них опишем отдельно, когда
появятся экраны. Модель лучше заложить сразу.

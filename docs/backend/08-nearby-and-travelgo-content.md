# 08. Места и маршруты рядом + раздел «TravelGo» в админке

Главная задача: **собственная система туристического контента TravelGo**.
Мы сами в админке добавляем страны, регионы, города, достопримечательности
с историей и готовые маршруты — и приложение показывает их пользователю
по его местоположению, без изменений в коде приложения.

На первом этапе весь контент создаёт только наша команда. Архитектура
должна позволить позже добавить маршруты гидов и пользователей (поле
`source` уже заложено, см. [02-content-model.md](02-content-model.md)).

Документ дополняет [02-content-model.md](02-content-model.md) (модель),
[03-mobile-content-api.md](03-mobile-content-api.md) (API приложения) и
[04-admin-api.md](04-admin-api.md) (API админки). Общие правила — в
[00-api-guidelines.md](00-api-guidelines.md).

## 1. Как это выглядит в приложении

Пользователь открывает приложение и разрешает геолокацию.

1. **Карта** — его точка и **достопримечательности рядом** (маркеры).
   Сначала ближайшие; при прокрутке списка или отдалении карты —
   дальше и дальше.
2. **Карточка достопримечательности** — фото, название, категория,
   расстояние, коротко. Нажатие → **экран места**: фото, описание,
   **история**, интересные факты, адрес, часы работы, в какие маршруты
   входит.
3. **Внизу — готовые маршруты.** Сначала маршруты города, где сейчас
   пользователь, затем соседних городов по расстоянию — до 100–200 км.
   Наши маршруты помечены **«Маршрут від TravelGo»**.
4. Пользователь **переместился** (другой район, другой город) —
   приложение само обновляет места и маршруты.

Без геолокации: приложение показывает выбранный вручную город (или
популярные маршруты) — те же запросы, но с координатами центра города.

## 2. Логика подбора

### 2.1. Где пользователь

По координатам сервер определяет:

- **город** — ближайший опубликованный город, в «зоне» которого стоит
  точка: расстояние до центра ≤ `City.radiusKm` (по умолчанию 15 км,
  для Киева/Парижа редактор ставит больше). Если точка в зонах двух
  городов — ближайший центр. Позже можно заменить на полигоны границ
  (`City.boundary`), API не изменится;
- **регион** и **страну** — через город; если города рядом нет — страну
  по координатам (обратный геокодер или полигоны стран), город = `null`.

### 2.2. Достопримечательности рядом

- Только `published` (и опубликованы город и страна — см. раздел 5).
- Сортировка **по расстоянию от пользователя** (по прямой).
- «Расширение радиуса» = постраничная выдача по расстоянию: первая
  страница — ближайшие 20, следующая — следующие 20 дальше, и так до
  предела `maxKm` (по умолчанию 50 км для мест). Сервер не ищет
  «по кругам» — просто отдаёт отсортированный по расстоянию список с
  курсором.
- Внутри одинакового расстояния (±100 м) — выше `priority` места
  (редактор отмечает главные: Эйфелева башня важнее безымянного фонтана).
- Фильтр по категориям (`category`) — как в настройках карты приложения.

### 2.3. Маршруты рядом

Порядок выдачи:

1. **Маршруты текущего города** (`scope: "city"`) — внутри: сначала
   официальные TravelGo (`isOfficial`), затем по `sortPriority`
   редактора, затем по популярности.
2. **Маршруты других городов** (`scope: "nearby"`) — по расстоянию от
   пользователя до **точки старта** маршрута, до `maxKm` (по умолчанию
   150, максимум 200).
3. Если ничего нет в 200 км — пустой список и `suggestion`: ближайшие
   города с маршрутами (дальше 200 км), чтобы экран не был пустым.

У каждого маршрута в ответе — `distanceKm` до старта и город.

### 2.4. Перемещение пользователя

Сервер ничего не хранит о перемещениях — каждый запрос самостоятельный.
Обновлять выдачу решает приложение:

| Что | Когда приложение перезапрашивает |
|---|---|
| Места рядом | Сдвиг > 300 м от точки прошлого запроса, или прошло > 10 мин |
| Маршруты рядом | Сменился город (`/geo/locate`), или сдвиг > 10 км |
| Где я (`/geo/locate`) | Сдвиг > 1 км |

### 2.5. Приватность координат

- Приложение отправляет координаты **округлёнными до 3 знаков** (~100 м):
  этого хватает для «рядом» и помогает кэшу.
- Сервер **не сохраняет** координаты пользователя и **не пишет их в
  логи** (в access-логах маскировать `lat`/`lng`). Используются только
  для ответа на запрос.
- Запросы работают и **без входа** (геолокация не привязывается к
  аккаунту). Если токен есть — заполняется `isSaved` у маршрутов.

Это же будет написано в политике конфиденциальности
(`docs/legal/privacy-policy.md`).

## 3. Модель данных — что добавляется

Полные таблицы — в [02-content-model.md](02-content-model.md). Новое и
изменённое:

```
Страна ─ Регион (необязательно) ─ Город ─┬─ Место (координаты, история)
                                         └─ Маршрут ─ старт → остановки → финиш
```

### Регион — `Region` (новое)

Область / регион / провинция — для группировки городов в админке и
фильтров («Львівська область», «Île-de-France»).

| Поле | Тип | Описание |
|---|---|---|
| `id` | `uuid` | |
| `countryCode` | `string` | Страна |
| `name` | `Localized` | |
| `status` | `ContentStatus` | Раздел 5 |
| `sortOrder` | `number` | |

### Город — `City` (дополнения)

| Поле | Тип | Описание |
|---|---|---|
| `regionId` | `uuid \| null` | Регион |
| `radiusKm` | `number` | «Зона» города для определения «пользователь в этом городе». По умолчанию 15 |
| `status` | `ContentStatus` | Вместо `isPublished` |

### Место — `Place` (дополнения)

| Поле | Тип | Описание |
|---|---|---|
| `category` | `string` | Категория: ключ из списка категорий карты приложения (`museum`, `monument`, `religion`, `palace`, `historic`, `architecture`, `park`, `viewpoint`, `square`, `bridge`, …). Список — в приложении `src/config/mapCategories.ts`, пришлём JSON |
| `shortDescription` | `Localized` | 1 предложение для карточки (бывшее `description`) |
| `description` | `Localized[]` | Подробное описание — абзацы |
| `history` | `Localized[]` | История места — абзацы |
| `facts` | `Localized[]` | «Цікаво знати» — 0–5 коротких фактов |
| `images` | `Image[]` | `{ url, credit }` — фото и автор/лицензия. Первое — главное |
| `visitMinutes` | `number` | Сколько обычно занимает осмотр (подставляется в маршрут по умолчанию) |
| `website` | `string \| null` | Официальный сайт |
| `priority` | `number` | 1–5, важность для сортировки «рядом» (5 — главные достопримечательности) |
| `status` | `ContentStatus` | Раздел 5 |

Место — самостоятельная сущность: публикуется отдельно и показывается
«рядом» даже если не входит ни в один маршрут.

### Маршрут — `Route` (дополнения)

| Поле | Тип | Описание |
|---|---|---|
| `regionId` | `uuid \| null` | Регион (для маршрутов по области; по умолчанию — регион города) |
| `isOfficial` | `boolean` | Официальный маршрут TravelGo → метка «Маршрут від TravelGo». Ставит админка; для `source.kind = "travelgo"` — `true` по умолчанию |
| `start` | `RoutePoint` | Начальная точка |
| `end` | `RoutePoint` | Конечная точка |
| `isLoop` | `boolean` | Кольцевой (финиш = старт) — тогда `end` не заполняется |
| `sortPriority` | `number` | Ручной порядок в выдаче города (больше — выше) |
| `path` | `LineString` | Линия маршрута по дорогам/тропам. Считает сервер по точкам (раздел 6), приложение рисует её на карте |
| `status` | `ContentStatus` | Раздел 5 |

`RoutePoint` — либо место, либо произвольная точка:

```json
{ "placeId": "…" }                                              // старт у достопримечательности
{ "name": { "uk": "Вихід метро Bir-Hakeim", "en": "Bir-Hakeim metro exit" },
  "latitude": 48.8539, "longitude": 2.2894 }                    // точка встречи
```

По умолчанию `start` = первая остановка, `end` = последняя. Если
указаны отдельно — линия маршрута идёт старт → остановки → финиш.

Для поиска «рядом» у маршрута хранится `startLocation` (точка старта,
`geography(Point)`), пересчитывается при сохранении.

## 4. API для мобильного приложения

Все пути от `/v1`. Тексты — строками на языке `Accept-Language`
(запасной — английский). Вход не нужен.

Координаты в запросах: `lat`, `lng` (WGS 84, до 3 знаков после точки).
Неверные — `400 INVALID_COORDINATES`.

### 4.1. Где я — `GET /geo/locate?lat=&lng=`

```json
{
  "city": { "id": "…", "name": "Париж", "distanceKm": 1.2, "timeZone": "Europe/Paris" },
  "region": { "id": "…", "name": "Іль-де-Франс" },
  "country": { "code": "FR", "name": "Франція" }
}
```

Нет города рядом → `"city": null` (страна — если удалось определить,
иначе тоже `null`). Это не ошибка.

### 4.2. Места рядом — `GET /places/nearby`

Параметры:

| Параметр | По умолчанию | Описание |
|---|---|---|
| `lat`, `lng` | — | Обязательно |
| `maxKm` | 50 | Предел расстояния (макс. 200) |
| `category` | все | Через запятую: `museum,monument` |
| `limit` | 20 | Макс. 50 |
| `cursor` | — | Из прошлого ответа |

```json
{
  "items": [
    {
      "id": "…",
      "name": "Лувр",
      "category": "museum",
      "shortDescription": "Найбільший художній музей світу.",
      "address": "Rue de Rivoli, 75001 Paris",
      "latitude": 48.8606,
      "longitude": 2.3376,
      "distanceKm": 0.1,
      "image": "https://cdn…/louvre-400.jpg",
      "hours": { "open": "09:00", "close": "18:00", "closedOn": [2] },
      "timeZone": "Europe/Paris",
      "city": { "id": "…", "name": "Париж" },
      "routesCount": 3
    }
  ],
  "nextCursor": "eyJkIjowLjE…"
}
```

- Порядок — раздел 2.2. Курсор кодирует последнее расстояние и `id`,
  чтобы страницы не повторялись и не пропускали.
- `nextCursor: null` — дальше в пределах `maxKm` ничего нет.

Для карты (маркеры в видимой области) — вариант без сортировки:
`GET /places/in-area?minLat=&minLng=&maxLat=&maxLng=&category=` →
до 200 мест `{ id, name, category, latitude, longitude, priority }`.
Область больше ~50×50 км — отдаём только `priority ≥ 4`.

### 4.3. Место целиком — `GET /places/{id}`

Всё из карточки плюс:

```json
{
  "description": ["Абзац…", "Абзац…"],
  "history": ["Палац Лувр збудували у XII столітті як фортецю…"],
  "facts": ["Щоб побачити всі експонати по 30 секунд, знадобиться 100 днів."],
  "images": [{ "url": "https://cdn…/louvre-1200.jpg", "credit": "© Wikimedia, CC BY-SA 4.0" }],
  "address": "Rue de Rivoli, 75001 Paris",
  "website": "https://www.louvre.fr",
  "visitMinutes": 120,
  "wiki": "uk:Лувр",
  "routes": [ /* RouteCard[] — опубликованные маршруты с этим местом */ ]
}
```

`?lat=&lng=` — необязательно: тогда в ответе есть `distanceKm`.

### 4.4. Маршруты рядом — `GET /routes/nearby`

| Параметр | По умолчанию | Описание |
|---|---|---|
| `lat`, `lng` | — | Обязательно |
| `maxKm` | 150 | Предел для маршрутов других городов (макс. 200) |
| `transport` | все | `walk`, позже `car` |
| `limit`, `cursor` | 20 | Пагинация |

```json
{
  "city": { "id": "…", "name": "Париж" },
  "items": [
    {
      "scope": "city",
      "distanceKm": 0.8,
      "route": { /* RouteCard из 03-mobile-content-api.md + поля ниже */ }
    },
    {
      "scope": "nearby",
      "distanceKm": 23.5,
      "route": { /* … маршрут в Версале … */ }
    }
  ],
  "nextCursor": null,
  "suggestion": null
}
```

Пусто в пределах `maxKm` → `items: []` и
`"suggestion": { "cities": [{ "id", "name", "distanceKm", "routesCount", "latitude", "longitude" }] }`
(координаты центра — приложение по нажатию покажет маршруты этого города)
— ближайшие города с маршрутами.

### 4.4а. Города — `GET /cities`

Для выбора города вручную, если человек не дал геолокацию: все
опубликованные города, где есть маршруты, по странам (`sortOrder`
страны, затем по алфавиту).

```json
[{ "id": "…", "name": "Київ", "country": { "code": "UA", "name": "Україна" },
   "latitude": 50.4501, "longitude": 30.5234, "routesCount": 5 }]
```

Приложение показывает маршруты и места выбранного города теми же
запросами «рядом» с координатами его центра.

### 4.5. Дополнения к `RouteCard` и маршруту целиком

В карточке (`RouteCard`, см. [03](03-mobile-content-api.md)) добавить:

```json
{
  "isOfficial": true,
  "coverCredit": "Rbrechko, CC BY-SA 4.0, Wikimedia Commons",
  "transport": "walk",
  "start": { "name": "Ейфелева вежа", "latitude": 48.8584, "longitude": 2.2945 },
  "region": { "id": "…", "name": "Іль-де-Франс" }
}
```

`coverCredit` — автор и лицензия обложки (`credit` фото); приложение
пишет его мелко на большом фото маршрута — этого требуют лицензии
CC BY / CC BY-SA. Так же — `credit` у фото мест.

`isOfficial: true` → приложение показывает метку **«Маршрут від
TravelGo»** (отдельно от `badge`: маршрут может быть и официальным, и
«Популярним»).

В `GET /routes/{id}` добавить `start`, `end` (с `name`, координатами и
`placeId`, если это место), `isLoop` и `path`:

```json
"path": { "type": "LineString", "coordinates": [[2.2945, 48.8584], [2.2950, 48.8590]] }
```

(GeoJSON: долгота, широта. Упростить до ~200–500 точек.)

### 4.6. Ошибки

| Код | Статус | Когда |
|---|---|---|
| `INVALID_COORDINATES` | 400 | `lat`/`lng` вне диапазона или не числа |
| `NOT_FOUND` | 404 | Место/маршрут не существует **или не опубликован** (скрытые и архивные для приложения не существуют) |
| `RATE_LIMITED` | 429 | Больше ~60 запросов «рядом» в минуту с IP |

### 4.7. Кэш и скорость

- Ответы «рядом» — `Cache-Control: max-age=120` (координаты округлены,
  поэтому соседние пользователи попадают в один кэш).
- Цель — ответ < 300 мс при 10 000 мест.

## 5. Статусы публикации контента

Один набор статусов для **всех** сущностей контента: страна, регион,
город, место, маршрут (и позже гид).

### 5.1. Статусы — `ContentStatus`

| Статус | Что значит | Видно в приложении |
|---|---|---|
| `draft` | Черновик: создаётся, заполняется | Нет |
| `in_review` | Готово, ждёт проверки вторым редактором (для своих — по желанию; для маршрутов пользователей — обязательно) | Нет |
| `scheduled` | Проверено, опубликуется автоматически в `publishAt` | Нет (до `publishAt`) |
| `published` | Опубликовано | **Да** (если опубликованы и «родители», 5.3) |
| `hidden` | Временно снято: сезонно закрыто, ремонт, правим ошибку. Ссылки и закладки сохраняются | Нет; в «Збережених» — «Тимчасово недоступно» |
| `rejected` | Отклонено при проверке (маршруты пользователей), с причиной | Нет |
| `archived` | Больше не используется. Хранится для истории и статистики, не удаляется | Нет; в «Збережених» — «Маршрут більше недоступний» |

Поля у каждой сущности: `status`, `publishAt` (для `scheduled`),
`publishedAt` (первая публикация), `statusReason` (для `hidden` /
`rejected`), `statusChangedAt`, `statusChangedBy`.

### 5.2. Переходы

```
draft ──► in_review ──► scheduled ──(publishAt)──► published
  │  ▲        │  │                                   │   ▲
  │  └────────┘  └──► rejected ──► draft             │   │
  └──────────────────────────────► published         ▼   │
                                                  hidden ┘
published / hidden / draft ──► archived ──(восстановить)──► draft
```

| Переход | Кто | Условие |
|---|---|---|
| `draft → in_review` | Редактор | — |
| `in_review → draft` | Редактор | Вернуть на доработку |
| `draft / in_review → published` | Редактор с правом публикации | Проверки 5.4 |
| `draft / in_review → scheduled` | То же | Проверки 5.4 + `publishAt` в будущем |
| `scheduled → published` | Сервер, по времени | Проверки повторяются; не прошли → `draft` + уведомление в админке |
| `scheduled → draft` | Редактор | Отменить публикацию |
| `in_review → rejected` | Редактор | `statusReason` обязателен |
| `rejected → draft` | Автор / редактор | Доработать |
| `published → hidden` | Редактор | `statusReason` (виден в админке) |
| `hidden → published` | Редактор | Проверки 5.4 |
| `* → archived` | Редактор | Кроме `archived` |
| `archived → draft` | Админ | Восстановить |

Удалять насовсем можно только `draft`, который никогда не публиковался.
Остальное — `archived`.

Правка опубликованного видна в приложении сразу (каждое сохранение — в
журнал изменений). Для больших переделок — `duplicate` в черновик и
замена.

### 5.3. Видимость в приложении — «родители»

Объект виден в приложении, только если `published` и он сам, и все его
«родители»:

| Объект | Родители |
|---|---|
| Регион | страна |
| Город | страна, регион (если указан) |
| Место | город (и выше) |
| Маршрут | город (и выше) + **все места-остановки** и места старта/финиша |

Скрыли город → в приложении пропадают его места и маршруты (их статусы
не меняются; вернули город — всё вернулось).

### 5.4. Проверки при публикации

Ответ `422 PUBLISH_CHECK_FAILED` со списком в `details.problems`.

| Объект | Обязательно |
|---|---|
| Страна | `name` на `en` и `uk` |
| Регион | `name` на `en` и `uk`; страна опубликована (или публикуется вместе) |
| Город | `name` на `en`/`uk`, координаты центра, `timeZone`, `radiusKm`, обложка; страна (и регион) опубликованы |
| Место | `name` и `shortDescription` на `en`/`uk`, `category`, координаты (не дальше `radiusKm × 3` от центра города), хотя бы 1 фото; город опубликован |
| Маршрут | как в [04](04-admin-api.md#проверки-при-публикации) + все остановки, старт и финиш `published`; посчитан `path` |

Предупреждения (публиковать можно): нет `history`, нет переводов
`de`/`es`/`fr`, у места нет часов работы, у фото нет `credit`.

Опубликовать «вместе»: `POST /admin/v1/publish` с массивом объектов
(страна + город + места + маршрут одним действием).

### 5.5. Снятие места, которое входит в маршруты

`hidden` / `archived` для места, которое входит в опубликованные
маршруты → `409 PLACE_IN_PUBLISHED_ROUTES`, в `details.routes` — список.
Редактор либо убирает место из маршрутов, либо подтверждает
(`?force=true`) — тогда эти маршруты автоматически переходят в `hidden`
с `statusReason: "place_unavailable"`.

## 6. Раздел «TravelGo» в админке

Отдельный раздел меню **TravelGo** — весь наш контент:

| Подраздел | Что делаем |
|---|---|
| **Страны** | Список, перевод названий, статус, порядок |
| **Регионы** | По странам; создать / править / статус |
| **Города** | Название, центр на карте, `radiusKm` (круг виден на карте), часовой пояс (подставляется по координатам), регион, обложка, статус |
| **Места** | Карта + список. Точка на карте (поиск адреса), категория, тексты на языках (коротко, описание, история, факты), фото с автором, часы работы, сайт, приоритет, статус. Видно, в каких маршрутах место |
| **Маршруты** | Тексты, обложка, способ передвижения, старт и финиш (место или точка на карте), остановки — добавить из мест города, порядок перетаскиванием, минуты на каждое. Отметка «Маршрут від TravelGo». Предпросмотр линии на карте. Статус |
| **Публикация** | Очередь `in_review`, запланированные `scheduled`, скрытые `hidden` — с фильтрами |
| **Журнал** | Кто, что и когда поменял (включая смену статусов) |

Права — по разделам и действиям (просмотр / создание / правка /
публикация / архив), как уже сделано для админов: редактор может
наполнять, публикует — тот, у кого есть право публикации.

### API админки (дополнения к [04](04-admin-api.md))

Все пути от `/admin/v1`.

| Запрос | Что делает |
|---|---|
| `GET/POST /regions`, `GET/PATCH /regions/{id}` | Регионы (фильтр `countryCode`) |
| `GET /places?cityId=&category=&status=&q=&bbox=` | Места с фильтрами (`bbox` — для карты) |
| `POST /{type}/{id}/status` | Смена статуса: `{ "to": "published", "publishAt": null, "reason": null }`. `type` — `countries`, `regions`, `cities`, `places`, `routes` |
| `POST /publish` | Опубликовать несколько объектов вместе: `{ "items": [{ "type": "cities", "id": "…" }, …] }` |
| `POST /routes/{id}/path/recalculate` | Пересчитать линию, длину и время по точкам |
| `GET /geo/timezone?lat=&lng=` | Часовой пояс по точке (для формы города) |
| `GET /geo/search?q=` | Поиск адреса → координаты (геокодер; для формы места) |
| `GET /audit?type=&id=` | Журнал изменений объекта |

Ответы при смене статуса: `422 PUBLISH_CHECK_FAILED`,
`409 INVALID_STATUS_TRANSITION` (переход не из таблицы 5.2),
`409 PLACE_IN_PUBLISHED_ROUTES`.

Старые `publish` / `unpublish` из [04](04-admin-api.md) можно оставить
как короткие пути к `POST /status`.

## 7. Как реализовать

- **PostgreSQL + PostGIS.** `Place.location`, `City.center`,
  `Route.startLocation` — `geography(Point, 4326)`, индексы GIST.
  «Ближайшие» — `ORDER BY location <-> :point` (KNN по индексу) с
  `ST_DWithin(location, :point, :maxKm * 1000)`; `distanceKm` —
  `ST_Distance`.
- **Линия маршрута** (`path`, `distanceKm`, `durationMinutes`) — сервис
  маршрутизации (OSRM / GraphHopper / Valhalla, профиль `foot` или
  `car` по `transport`) при сохранении остановок; результат хранить, не
  считать на каждый запрос. Нет сервиса — прямые отрезки ×1.3.
- **Тексты** — те же `Localized` (JSONB) с поиском по всем языкам.
- **Фото** — как в [04](04-admin-api.md#загрузка-картинок): копии 400 и
  1200 px, в мобильное API — ссылки на нужный размер.
- Расстояния в ответах — по прямой (до старта / до места). Время пешком
  до места — позже.

## 8. Порядок работ и сдача

1. Модель (регионы, поля мест и маршрутов, статусы) + раздел «TravelGo»
   в админке: страны → регионы → города → места → маршруты, смена
   статусов с проверками.
2. Мобильное API: `/geo/locate`, `/places/nearby`, `/places/in-area`,
   `/places/{id}`, `/routes/nearby`, дополнения `RouteCard` и
   `/routes/{id}`. Описать в `openapi.yaml`.
3. Импорт стартового контента: 15 маршрутов, места и гиды из
   приложения (`src/data/mock*.ts` — выгрузим в JSON).
4. Пересчёт `path` сервисом маршрутизации.
5. Запланированная публикация, журнал.

Как сдаём: на staging опубликованы хотя бы Киев, Львов и Париж с
местами и маршрутами; запросы для точек «центр Киева», «Бровары» (соседний
город), «середина поля в 300 км от городов» дают ожидаемые ответы
(текущий город, соседний, `suggestion`). Мы подключаем в приложении и
присылаем замечания.

## 9. Что сделает приложение

Когда появится API (п. 2):

- главная: карта с нашими местами рядом + список карточек по
  расстоянию; при сдвиге пользователя — обновление по правилам 2.4;
- экран места: фото, описание, история, факты, маршруты с этим местом;
- маршруты внизу: «у вашому місті» → «поруч» с расстоянием, метка
  «Маршрут від TravelGo»;
- маршрут на карте — по `path`, старт и финиш отдельными маркерами;
- в «Збережених» — пометки «Тимчасово недоступно» / «Більше недоступний»;
- тексты про геолокацию в «Частых вопросах» и «Дозволах» — обновим:
  приблизные координаты уходят на сервер для поиска рядом и не хранятся.

До готовности API приложение работает на встроенных тестовых данных.

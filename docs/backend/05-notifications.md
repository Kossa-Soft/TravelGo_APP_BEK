# 05. Уведомления

Список уведомлений в приложении, отметка «прочитано», настройки и
push-уведомления. Общие правила — в [00-api-guidelines.md](00-api-guidelines.md).

## Как это выглядит в приложении

- На иконке «Профіль» в нижнем меню — оранжевая точка, если есть
  непрочитанные. В профиле у пункта «Сповіщення» — их число.
- Экран «Сповіщення»: группы «Сегодня / Вчера / Раньше», у каждого
  иконка, заголовок, текст, время. Непрочитанные — белые с оранжевой
  точкой, прочитанные — приглушённые.
- Нажатие на уведомление отмечает его прочитанным; кнопка «Прочитать всё».
- Шестерёнка справа вверху — настройки.

Уведомлений немного (новые города, маршруты, обновления), поэтому всё
максимально просто: без удаления, архива и фильтров.

## Категории

Каждое уведомление относится к одной категории. Категория = переключатель
в настройках.

| `category` | Что | По умолчанию | Можно выключить |
|---|---|---|---|
| `cities` | Новые города и достопримечательности | вкл. | да |
| `routes` | Новые и обновлённые маршруты (в т.ч. изменения в сохранённых) | вкл. | да |
| `appUpdates` | Обновления приложения | вкл. | да |
| `recommendations` | Рекомендации и предложения (маркетинг) | **выкл.** | да |
| `system` | Безопасность аккаунта: вход с нового устройства, смена пароля или номера | вкл. | **нет** |

- `recommendations` по умолчанию выключены: маркетинговые сообщения — только
  с согласия пользователя (GDPR, правила App Store и Google Play).
- `system` выключить нельзя: это предупреждения о безопасности.
- Плюс общий переключатель `enabled`: выключен — не отправляем ничего,
  кроме `system`.

## Уведомление — `Notification`

```json
{
  "id": "9c1f…",
  "category": "cities",
  "title": "Додано нове місто!",
  "body": "Тепер доступні пам'ятки та маршрути нового міста.",
  "createdAt": "2026-11-23T09:13:00Z",
  "read": false,
  "link": { "type": "city", "id": "…" }
}
```

- `title` и `body` — уже на языке пользователя (`Accept-Language` или
  `language` из профиля), запасной — английский. Текст может быть длинным:
  приложение показывает его целиком.
- `link` — необязательно: куда вести по нажатию (`city`, `route`,
  `guide`, `appStore`). Пока приложение только отмечает прочитанным,
  переходы добавим позже.
- Хранить 90 дней, потом удалять.

## Эндпоинты

Все пути от `/v1`, нужен вход.

| Запрос | Что делает |
|---|---|
| `GET /me/notifications?cursor=&limit=` | Список, новые сверху (пагинация как везде) |
| `GET /me/notifications/unread-count` | `{ "count": 2 }` — для точки в меню |
| `POST /me/notifications/{id}/read` | Отметить прочитанным → `204` (повторно — не ошибка) |
| `POST /me/notifications/read-all` | Прочитать всё → `204` |
| `GET /me/notification-settings` | Настройки (ниже) |
| `PATCH /me/notification-settings` | Изменить одно или несколько полей → новые настройки |

```json
// GET /me/notification-settings
{
  "enabled": true,
  "cities": true,
  "routes": true,
  "appUpdates": true,
  "recommendations": false
}
```

`system` в настройках не передаётся — он всегда включён.

Приложение запрашивает `unread-count` при запуске, при возвращении в
приложение и после push. Отдельного «реального времени» (WebSocket) не нужно.

## Push-уведомления

Чтобы уведомления приходили на экран телефона, когда приложение закрыто:

1. Приложение получает токен устройства (Firebase Cloud Messaging для
   Android, APNs через Firebase для iOS) и отправляет:

   ```json
   // POST /me/devices
   { "token": "…", "platform": "ios", "language": "uk" }   →   204
   ```

   При выходе — `DELETE /me/devices/{token}`.
2. Сервер при создании уведомления сохраняет его в списке и, если
   категория включена в настройках, отправляет push на все устройства
   пользователя. В push — тот же `title` / `body` и `id` уведомления
   (по нажатию приложение откроет список).
3. Токены, на которые FCM/APNs отвечают «недействителен», удалять.

Сейчас в приложении push ещё не подключён (нужна настройка Firebase и
сертификатов Apple). Список уведомлений и настройки работают уже сейчас
(на тестовых данных).

## Кто создаёт уведомления

- **Админка** — рассылка по категории: заголовок и текст на языках,
  категория, необязательная ссылка, кому (всем / по стране / по языку),
  время отправки. Пример: «Добавлен новый город!» при публикации города.
- **Сервер автоматически** — `system` (смена пароля или номера, вход с
  нового устройства); `routes` — изменение маршрута, который
  пользователь сохранил.

API рассылки в админке:

| Запрос | Что делает |
|---|---|
| `POST /admin/v1/notifications` | Создать рассылку (`category`, `title`/`body` как `Localized`, `link`, `audience`, `sendAt`) |
| `GET /admin/v1/notifications` | История рассылок: сколько отправлено и прочитано |

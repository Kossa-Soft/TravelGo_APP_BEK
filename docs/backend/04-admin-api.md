# 04. API админки: страны, города, места, маршруты

Задача: чтобы в админке можно было **создавать и публиковать маршруты по
странам и городам** без участия разработчиков. Модель данных — в
[02-content-model.md](02-content-model.md), общие правила — в
[00-api-guidelines.md](00-api-guidelines.md).

> **Раздел «TravelGo» в админке, регионы, статусы публикации и их
> переходы, старт/финиш маршрута** — в
> [08-nearby-and-travelgo-content.md](08-nearby-and-travelgo-content.md#6-раздел-travelgo-в-админке).
> Где документы расходятся — верен 08.

Все пути от `/admin/v1`. Тексты здесь — объекты `Localized` целиком
(`{ "uk": …, "en": …, … }`), а не строки.

## Сдача этапа 3

Раздел TravelGo доступен авторизованному администратору с выданными правами. Запросы `/admin/v1` используют сессию админки и CSRF для операций записи. Мобильное приложение использует свой контракт из [openapi.yaml](../../openapi.yaml).

- Страны определяются по ISO-коду в административных путях. Для остальных объектов используется UUID.
- Статус меняется через `POST /{type}/{id}/status`. Публикация группы объектов выполняется через `POST /publish` с проверкой всех зависимостей.
- Остановка содержит `placeId`, `visitMinutes` и необязательный `note` с переводами. Линия рассчитывается при сохранении остановок или отдельным запросом пересчёта.
- Имена и описания редактируются на пяти языках. Фото места имеют поле `credit`, а обложки города и маршрута поддерживают `coverCredit`.
- Поиск адресов, определение часового пояса по точке и расчёт пешего пути по дорогам используют настроенные провайдеры. Без них редактор может указать координаты и часовой пояс вручную. В таком режиме линия маршрута рассчитывается ориентировочно по точкам.

## Как редактор работает в админке

1. Выбирает **страну** (или добавляет новую).
2. Выбирает **город** (или создаёт: название на языках, точка на карте,
   часовой пояс, обложка).
3. Добавляет в город **места**: название и описание на языках, точка на
   карте, адрес, часы работы, фото.
4. Создаёт **маршрут** в городе: название, короткое и полное описание,
   обложка, автор (TravelGo или гид), метка.
5. Добавляет в маршрут **остановки**: выбирает места города, расставляет
   порядок перетаскиванием, задаёт минуты на каждое место.
6. Смотрит **предпросмотр** на карте и **публикует**.

Навигация в админке: Страны → Города страны → Маршруты города, плюс
общий список маршрутов с фильтрами.

## Доступ и роли

Административная учётная запись использует почту, пароль и 2FA. Суперадминистратор управляет администраторами и может выдать полный доступ к TravelGo или отдельные права по разделам. Для каждой сущности доступны просмотр, создание, правка, публикация, архивирование и удаление. Для очереди публикации, журнала и настроек AlphaSMS выдаются свои разрешения.

Журнал фиксирует, кто выполнил операцию, когда она произошла и какие поля или статусы изменились.

## Страны

| Запрос | Что делает |
|---|---|
| `GET /countries?q=&status=` | Список, с числом городов и маршрутов |
| `POST /countries` | `{ "code": "FR", "name": {…}, "sortOrder": 10 }` |
| `PATCH /countries/{code}` | Правка (статус — через `POST /countries/{code}/status`, см. 08) |

Страна без опубликованных городов в приложении не видна (в `GET /countries` попадают только страны с маршрутами). Страну и первый город удобно публиковать вместе — `POST /admin/v1/publish` (08).

## Города

| Запрос | Что делает |
|---|---|
| `GET /countries/{code}/cities` | Города страны (+ число мест и маршрутов) |
| `POST /cities` | Создать |
| `GET /cities/{id}` | Город |
| `PATCH /cities/{id}` | Правка (статус — через `POST /cities/{id}/status`) |
| `DELETE /cities/{id}` | Только если в нём нет маршрутов |

```json
// POST /cities
{
  "countryCode": "FR",
  "name": { "uk": "Париж", "en": "Paris" },
  "latitude": 48.8566,
  "longitude": 2.3522,
  "timeZone": "Europe/Paris",
  "coverImage": "https://cdn…/paris.jpg"
}
```

`timeZone` можно подставлять автоматически по координатам (например,
библиотекой tz-lookup), редактор только проверяет.

## Места

| Запрос | Что делает |
|---|---|
| `GET /cities/{id}/places?q=` | Места города (поиск по названию на всех языках) |
| `POST /places` | Создать |
| `GET /places/{id}` | Место + в каких маршрутах используется |
| `PATCH /places/{id}` | Правка |
| `DELETE /places/{id}` | Только если не входит ни в один маршрут |

```json
// POST /places
{
  "cityId": "…",
  "name": { "uk": "Ейфелева вежа", "en": "Eiffel Tower" },
  "shortDescription": { "uk": "Символ Парижа…", "en": "The symbol of Paris…" },
  "address": "Champ de Mars, 5 Av. Anatole France, 75007 Paris",
  "latitude": 48.8584,
  "longitude": 2.2945,
  "hours": { "open": "09:30", "close": "23:45" },
  "images": [{ "url": "https://cdn…/eiffel.jpg", "credit": "TravelGo" }],
  "wiki": "uk:Ейфелева_вежа"
}
```

Проверки: точка места не дальше ~50 км от центра города (защита от
ошибки в координатах); `hours.open`/`close` в формате `HH:MM`.

Удобно (не обязательно в первой версии): поиск адреса и координат по
названию (геокодер) и подтягивание описания из Википедии.

## Маршруты

| Запрос | Что делает |
|---|---|
| `GET /routes?countryCode=&cityId=&status=&source=&guideId=&q=` | Список с фильтрами |
| `POST /routes` | Создать черновик |
| `GET /routes/{id}` | Маршрут целиком, с остановками |
| `PATCH /routes/{id}` | Правка полей |
| `PUT /routes/{id}/stops` | Заменить список остановок целиком (порядок = порядок в массиве) |
| `POST /routes/{id}/status` с `to: "published"` | Опубликовать (с проверками ниже) |
| `POST /routes/{id}/status` с `to: "hidden"` | Снять с публикации (→ `hidden`) |
| `POST /routes/{id}/duplicate` | Копия в черновик — для похожего маршрута |
| `DELETE /routes/{id}` | Только черновики; опубликованные — в `archived` |

```json
// POST /routes
{
  "cityId": "…",
  "source": { "kind": "travelgo" },
  "title": { "uk": "Класичний Париж", "en": "Classic Paris" },
  "description": { "uk": "Найвідоміші пам'ятки…", "en": "The most famous sights…" },
  "about": [
    { "uk": "Перший абзац…", "en": "First paragraph…" }
  ],
  "coverImage": "https://cdn…/classic-paris.jpg",
  "badge": "editorsChoice"
}
```

```json
// PUT /routes/{id}/stops
[
  { "placeId": "…eiffel",  "visitMinutes": 20 },
  { "placeId": "…trocadero", "visitMinutes": 15 },
  { "placeId": "…louvre",  "visitMinutes": 90, "note": { "uk": "Вхід з піраміди", "en": "Enter through the pyramid" } }
]
```

После изменения остановок сервер пересчитывает:
- `placesCount`;
- `distanceKm` — длина по точкам с профилем по `transport` (`walk` —
  пешеходный, `car` — автомобильный; сервис маршрутов, например
  OSRM/GraphHopper; на крайний случай — по прямой ×1.3);
- `durationMinutes` — время в пути (по тому же профилю) + сумма `visitMinutes`. Редактор может
  поправить вручную (тогда автоматический пересчёт для поля отключается).

### Проверки при публикации

`POST /routes/{id}/status` с `to: "published"` отвечает `422 PUBLISH_CHECK_FAILED` со
списком проблем в `details.problems`, если:

- нет `title`, `description` или `about` на `en` или `uk`;
- нет обложки;
- меньше 2 остановок;
- остановка из другого города;
- город или страна не опубликованы (или публиковать их вместе);
- у маршрута гида не указан гид.

Предупреждения (публиковать можно): нет перевода на `de` / `es` / `fr`,
у места нет фото, у места нет часов работы.

## Модерация маршрутов пользователей

Маршруты с `source.kind = "user"` приходят в статусе `in_review`.

| Запрос | Что делает |
|---|---|
| `GET /moderation/routes` | Очередь на проверку |
| `POST /routes/{id}/approve` | Одобрить → `published` |
| `POST /routes/{id}/reject` | `{ "reason": "…" }` → `rejected`, причину увидит автор |

## Гиды

| Запрос | Что делает |
|---|---|
| `GET /guides?q=&cityId=` | Список |
| `POST /guides` | Создать (имя, должность, био, фото, обложка, контакты, города) |
| `PATCH /guides/{id}` | Правка, в т.ч. `verified` |

Маршрут гида создаётся как обычный маршрут с
`"source": { "kind": "guide", "guideId": "…" }`.

## Загрузка картинок

`POST /{type}/{id}/images` принимает поле `file` в `multipart/form-data` и необязательное поле `credit`. Поддерживаются JPEG, PNG и WebP до 10 МБ. Сервер сохраняет версии до 400 и 1200 пикселей и возвращает `fileUrl` и `thumbnailUrl`. Для места файл добавляется в список фотографий. Для города и маршрута заменяется обложка и сохраняется её авторство.

Черновые фото доступны через сессию админки. Выдачу опубликованных фото мобильному приложению подключаем вместе с этапом 4.

## Пользователи приложения (минимум)

| Запрос | Что делает |
|---|---|
| `GET /users?phone=` | Найти по номеру |
| `PATCH /users/{id}` | Поменять `plan` / `planUntil` вручную (пока нет оплаты в сторах), заблокировать |

## Импорт тестовых маршрутов

Стартовый JSON-каталог опубликован в мобильной ветке `main` на коммите [`1bd2b80`](https://github.com/Kossa-Soft/TravelGo_APP/tree/1bd2b80/content). На этапе 4 загружаем страны, регионы, города, места и маршруты в этом порядке. Стабильные слаги позволяют повторить импорт без создания дублей. Требования к формату и источникам фото приведены в [инструкции к каталогу](https://github.com/Kossa-Soft/TravelGo_APP/blob/1bd2b80/content/README.md).

## Порядок работ (предложение)

1. Авторизация по телефону + `/me` ([01-auth.md](01-auth.md)).
2. Модель контента + админка: страны → города → места → маршруты →
   публикация.
3. Мобильное API: маршрут целиком, списки, поиск, гиды.
4. Сохранённые маршруты.
5. Модерация, отзывы, прохождения, оплата PRO.

# 01. Авторизация по номеру телефона

Регистрация, вход, восстановление пароля и профиль. Общие правила
(формат ошибок, токены) — в [00-api-guidelines.md](00-api-guidelines.md).

## Как это выглядит в приложении

Экраны уже готовы и работают на тестовых данных:

1. **Регистрация:** номер телефона (с выбором страны) + пароль →
   SMS с кодом из 4 цифр → «Спасибо! Вы успешно зарегистрированы» →
   пользователь сразу внутри приложения.
2. **Вход:** номер + пароль.
3. **Восстановление пароля:** «Забыли пароль?» → номер → SMS-код →
   новый пароль дважды → «Пароль изменён» → вход.

Имени и почты при регистрации нет — только телефон и пароль.

## Правила

| Что | Правило |
|---|---|
| Номер | E.164 (`+380978670317`). Приложение уже нормализует; сервер всё равно проверяет формат (например, библиотекой libphonenumber) |
| Пароль | Минимум 8 символов, без других требований. Хранить хеш (Argon2id или bcrypt) |
| SMS-код | 4 цифры, действует **10 минут**, максимум **5 попыток** ввода, хранить хеш |
| Повторная отправка | Не раньше чем через **45 секунд** (в приложении таймер 45 с). Не больше 5 SMS на номер в час |
| Лимиты | Вход: 10 попыток на номер за 15 минут, потом `429`. Плюс общий лимит по IP |
| SMS-провайдер | На выбор бэкенда (Twilio, Vonage, местные). Важны доставка в Украину и ЕС и защита от SMS-накрутки (SMS pumping): лимиты по стране и IP |

## Тестовый пользователь

На **staging** и для проверки приложения в App Store / Google Play
(ревьюерам нужен рабочий вход):

| Поле | Значение |
|---|---|
| Телефон | `+380978670317` |
| Пароль | `123456789` |
| SMS-код | `1610` — для этого номера SMS не отправляется, код всегда `1610` |

На проде фиксированный код допустим только для этого одного номера
(список «белых» номеров в конфиге), иначе — дыра в безопасности.

## Эндпоинты

Все пути от `/v1`. Без токена — кроме `/me`.

### Регистрация

#### `POST /auth/register/start`

Проверяет номер, сохраняет пароль во временную заявку и отправляет SMS.

```json
// запрос
{ "phone": "+380978670317", "password": "123456789" }

// ответ 200
{
  "verificationId": "c1b2…",
  "expiresIn": 600,      // секунд до истечения кода
  "resendIn": 45,        // секунд до возможности переотправить
  "codeLength": 4
}
```

Ошибки: `INVALID_PHONE` (400), `WEAK_PASSWORD` (422),
`PHONE_ALREADY_REGISTERED` (409), `RATE_LIMITED` (429).

Аккаунт создаётся **только после подтверждения кода**. Неподтверждённые
заявки удалять через 24 часа.

#### `POST /auth/register/verify`

```json
// запрос
{ "verificationId": "c1b2…", "code": "1610" }

// ответ 201
{
  "accessToken": "…",
  "refreshToken": "…",
  "user": { … }          // как в GET /me
}
```

Ошибки: `WRONG_CODE` (422, в `details.attemptsLeft` — сколько осталось),
`CODE_EXPIRED` (422), `TOO_MANY_ATTEMPTS` (429), `VERIFICATION_NOT_FOUND` (404).

### Повторная отправка кода

#### `POST /auth/code/resend`

Общий для регистрации и восстановления.

```json
// запрос
{ "verificationId": "c1b2…" }

// ответ 200
{ "expiresIn": 600, "resendIn": 45 }
```

Ошибки: `RESEND_TOO_EARLY` (429, `details.retryAfter`), `VERIFICATION_NOT_FOUND`.
Новый код заменяет старый, счётчик попыток сбрасывается.

### Вход

#### `POST /auth/login`

```json
// запрос
{ "phone": "+380978670317", "password": "123456789" }

// ответ 200
{ "accessToken": "…", "refreshToken": "…", "user": { … } }
```

Ошибки:
- `PHONE_NOT_FOUND` (404) — приложение пишет «Аккаунт с таким номером не найден»;
- `WRONG_PASSWORD` (401) — «Неверный пароль»;
- `RATE_LIMITED` (429).

> Раздельные ошибки удобны пользователю, но позволяют проверить, есть ли
> номер в базе. Защита — жёсткие лимиты (см. «Правила»). Если решим
> скрывать — вернуть общую `INVALID_CREDENTIALS`, приложение подстроим.

### Обновление токенов и выход

#### `POST /auth/refresh`

```json
{ "refreshToken": "…" }   →   { "accessToken": "…", "refreshToken": "…" }
```

Ошибка `TOKEN_EXPIRED` / `UNAUTHORIZED` (401) — приложение отправит на вход.

#### `POST /auth/logout`

```json
{ "refreshToken": "…" }   →   204
```

### Восстановление пароля

#### `POST /auth/password/forgot`

```json
// запрос
{ "phone": "+380978670317" }

// ответ 200 — как у register/start
{ "verificationId": "…", "expiresIn": 600, "resendIn": 45, "codeLength": 4 }
```

Ошибки: `PHONE_NOT_FOUND` (404) — приложение пишет «Аккаунт с таким
номером не найден»; `RATE_LIMITED` (429).

#### `POST /auth/password/verify`

```json
// запрос
{ "verificationId": "…", "code": "1610" }

// ответ 200
{ "resetToken": "…", "expiresIn": 900 }   // одноразовый, 15 минут
```

Ошибки — как у `register/verify`.

#### `POST /auth/password/reset`

```json
// запрос
{ "resetToken": "…", "newPassword": "новый-пароль" }

// ответ 204
```

После смены: отозвать **все** refresh-токены пользователя. Приложение
показывает «Пароль изменён» и ведёт на вход (автоматически не входит).

Ошибки: `WEAK_PASSWORD` (422), `RESET_TOKEN_INVALID` (401).

### Профиль

#### `GET /me`

```json
{
  "id": "4f1e…",
  "phone": "+380978670317",
  "firstName": null,            // null, пока не заполнено
  "lastName": null,
  "middleName": null,           // необязательно
  "birthDate": null,            // "1990-05-21"
  "avatarUrl": null,
  "language": "uk",
  "plan": "pro",                // "free" | "pro"
  "planUntil": "2026-12-18",    // null для free
  "createdAt": "2026-11-23T10:00:00Z"
}
```

При регистрации имени нет. Пока `firstName` и `lastName` пустые,
приложение показывает временное имя «Мандрівник 0317» (последние 4 цифры
номера) и предлагает заполнить профиль. Временное имя на сервере
**не хранить** — это только отображение.

В профиле приложение показывает имя, инициалы и «PRO — до 18.12.2026».

#### `PATCH /me` — личные данные

```json
{
  "firstName": "Сергій",
  "lastName": "Коба",
  "middleName": "",
  "birthDate": "1990-05-21",
  "language": "uk"
}
```

Частичное обновление (передаются только изменённые поля). Проверки:
- `firstName`, `lastName` — 1–50 символов, буквы любого языка, пробел,
  дефис, апостроф (`INVALID_NAME`, 422);
- `middleName` — необязательное, те же правила;
- `birthDate` — существующая дата, не в будущем, год ≥ 1900
  (`INVALID_DATE`, 422).

Язык сохраняем, чтобы слать SMS и уведомления на языке пользователя.

#### Фото профиля

`POST /me/avatar` — загрузка, `multipart/form-data`, поле `file`.

```
Content-Type: multipart/form-data
file: <jpeg|png|webp>      // приложение уже сжимает до 600×600, ~50–150 КБ

→ 200  { "avatarUrl": "https://cdn…/avatars/4f1e…/a1b2.jpg" }
```

- Принимать JPEG, PNG, WebP (HEIC — по желанию: на iPhone приложение
  отдаёт JPEG), до 5 МБ. Иначе `INVALID_IMAGE` (422) / `FILE_TOO_LARGE` (413).
- На сервере: обрезать по центру в квадрат, сделать 256 и 512 px, убрать
  EXIF (там бывает геолокация — это персональные данные).
- Каждый раз новый URL (не перезаписывать файл) — иначе телефоны покажут
  старое фото из кэша.
- `avatarUrl` появляется в `GET /me`.

`DELETE /me/avatar` → `204`. Фото удалить из хранилища, `avatarUrl = null`.

#### `POST /me/password/verify` — проверка текущего пароля

Нужна для первого шага смены номера (пользователь сначала вводит пароль,
потом новый номер).

```json
{ "password": "…" }   →   204
```

Ошибки: `WRONG_PASSWORD` (401), `RATE_LIMITED` (429 — те же лимиты, что
у входа: перебор пароля через этот метод недопустим).

#### Смена номера телефона

Два шага — так же, как в приложении: сначала пароль, потом код на
**новый** номер.

`POST /me/phone/start`

```json
// запрос
{ "password": "123456789", "newPhone": "+380501234567" }

// ответ 200
{ "verificationId": "…", "expiresIn": 600, "resendIn": 45, "codeLength": 4 }
```

Ошибки: `WRONG_PASSWORD` (401), `INVALID_PHONE` (400),
`SAME_PHONE` (422 — это текущий номер), `PHONE_ALREADY_REGISTERED` (409),
`RATE_LIMITED` (429).

`POST /me/phone/verify`

```json
{ "verificationId": "…", "code": "1610" }   →   200, тело как у GET /me
```

После смены:
- старый номер больше не подходит для входа;
- на **старый** номер отправить SMS «Номер вашего аккаунта изменён»
  (если это сделал не владелец — он узнает сразу);
- создать системное уведомление (см. [05-notifications.md](05-notifications.md));
- остальные сессии можно не отзывать (пароль тот же), но это на выбор.

Повторная отправка кода — общий `POST /auth/code/resend`.

#### `POST /me/password` — смена пароля из профиля

```json
{ "currentPassword": "…", "newPassword": "…" }   →   204
```

Ошибки:
- `WRONG_PASSWORD` (401) — неверный текущий;
- `WEAK_PASSWORD` (422) — меньше 8 символов;
- `SAME_PASSWORD` (422) — новый совпадает с текущим.

После смены отозвать refresh-токены других устройств (текущее остаётся
в системе) и создать системное уведомление «Пароль изменён». В
приложении есть ссылка «Забыли текущий пароль?» — она ведёт в обычное
восстановление пароля.

#### `DELETE /me` — удаление аккаунта

**Обязательно:** Apple (правило 5.1.1(v)) и Google Play требуют
удаления аккаунта прямо из приложения. Удаляем персональные данные,
отзываем токены. Подтверждение — паролем:

```json
{ "password": "…" }   →   204
```

## Таблицы (ориентир)

- `users` — id, phone (уникальный), password_hash, first_name, last_name,
  middle_name, birth_date, language, plan,
  plan_until, created_at, deleted_at.
- `phone_verifications` — id, phone, purpose (`register` | `reset` | `change_phone`),
  code_hash, attempts, expires_at, resend_at, pending_password_hash
  (для регистрации), consumed_at.
- `refresh_tokens` — id, user_id, token_hash, expires_at, revoked_at,
  device (необязательно).

## Подписка PRO (на будущее)

Сейчас `plan` и `planUntil` можно менять вручную в админке. Позже
покупка будет через App Store и Google Play: приложение передаёт чек,
сервер проверяет его у Apple / Google и продлевает `planUntil`. Отдельный
документ напишем, когда определимся с ценой и названием подписки.

# 00. Общие правила API

Документ для разработчика бэкенда TravelGo. Описывает соглашения, общие
для всех эндпоинтов. Конкретные методы — в файлах `01`–`04`.

## Что такое TravelGo

Мобильное приложение (iOS и Android, React Native) с пешеходными
маршрутами по городам: карта, места, маршруты от команды TravelGo, гидов
и пользователей. Интерфейс на 5 языках: украинский, английский, немецкий,
испанский, французский.

Сейчас приложение работает на тестовых данных, зашитых в код. Бэкенд
должен их заменить. Форма данных в документах повторяет то, что
приложение уже использует, — это упростит подключение.

## Базовые правила

| Тема | Правило |
|---|---|
| Стиль | REST + JSON, UTF-8 |
| Адреса | Мобильное приложение: `https://api.<домен>/v1/...`; админка: `https://api.<домен>/admin/v1/...` |
| Версия | В пути (`/v1`). Несовместимые изменения — только в `/v2`; старые версии приложения живут в сторах месяцами |
| Имена полей | `camelCase` (`durationMinutes`, `planUntil`) |
| Идентификаторы | UUID (строка). Для стран — ISO-код (`UA`, `IT`) |
| Даты и время | ISO 8601 в UTC: `2026-12-18T00:00:00Z`. Дата без времени — `2026-12-18` |
| Время работы мест | Локальное время места `"09:30"` + часовой пояс города (IANA, `Europe/Paris`) |
| Телефоны | Только E.164: `+380978670317`. Приложение уже отправляет в этом формате |
| Координаты | `latitude`, `longitude` — числа (WGS 84) |
| Картинки | Абсолютные HTTPS-URL, лучше через CDN. Отдавать в разумном размере (обложка ≤ 1600 px по ширине) |
| Пустые поля | Необязательное поле без значения — не передавать или `null`, но одинаково во всём API |

## Ответы

Успешный ответ — сразу объект или список, без лишних обёрток:

```json
{ "id": "…", "title": "Класичний Париж" }
```

Списки — с пагинацией по курсору:

```json
{
  "items": [ … ],
  "nextCursor": "eyJpZCI6Ij…"   // null — больше нет
}
```

Параметры списка: `?limit=20&cursor=…` (`limit` по умолчанию 20, максимум 100).

## Ошибки

HTTP-статус + единый формат тела:

```json
{
  "error": {
    "code": "WRONG_PASSWORD",
    "message": "Wrong password",
    "field": "password",
    "details": {}
  }
}
```

- `code` — стабильная машинная строка. **Приложение показывает текст по
  `code`** (переводы на 5 языков у нас), а не `message`.
- `message` — для логов и отладки, на английском.
- `field` — какое поле подсветить красным (если ошибка про поле).
- `details` — доп. данные, например `{ "retryAfter": 30 }`.

Статусы:

| Статус | Когда |
|---|---|
| 400 | Неверный формат запроса (`VALIDATION_ERROR`) |
| 401 | Нет токена или он истёк (`UNAUTHORIZED`, `TOKEN_EXPIRED`) |
| 403 | Нет прав (`FORBIDDEN`) |
| 404 | Не найдено (`NOT_FOUND`, `PHONE_NOT_FOUND`) |
| 409 | Конфликт (`PHONE_ALREADY_REGISTERED`) |
| 422 | Бизнес-правило (`WRONG_CODE`, `WEAK_PASSWORD`) |
| 429 | Слишком часто (`RATE_LIMITED`, в `details.retryAfter` — секунды) |
| 500 | Ошибка сервера |

Полный список кодов для авторизации — в [01-auth.md](01-auth.md).

## Авторизация

- Вход выдаёт пару токенов:
  - `accessToken` — короткий (15 минут), передаётся в заголовке
    `Authorization: Bearer <token>`;
  - `refreshToken` — длинный (60 дней), только для обновления пары.
- Пользователь входит один раз и остаётся в приложении: приложение само
  обновляет токены через `POST /v1/auth/refresh`.
- Refresh-токены — одноразовые (ротация): при обновлении старый
  становится недействительным.
- Выход и смена пароля отзывают refresh-токены.
- Подробности — в [01-auth.md](01-auth.md).

## Языки

- Приложение передаёт язык интерфейса: `Accept-Language: uk` (одно из
  `uk`, `en`, `de`, `es`, `fr`).
- **Мобильное API** возвращает тексты уже на этом языке. Если перевода
  нет — на английском (английский обязателен для любого текста).
- **Админка** работает с переводами целиком:

  ```json
  "title": { "uk": "Класичний Париж", "en": "Classic Paris", "de": null }
  ```

- Когда пользователь меняет язык, приложение перезапрашивает данные.

## Безопасность и надёжность

- Только HTTPS.
- Лимиты запросов на авторизацию (по номеру и по IP) — см. `01-auth.md`.
- Пароли и SMS-коды хранить только в виде хешей. Не писать их, токены и
  номера целиком в логи.
- CORS — только для домена админки. Мобильному приложению CORS не нужен.
- Идемпотентность создания в админке — заголовок `Idempotency-Key`
  (по желанию, но полезно при плохой сети).

## Документация API

- Описать API в **OpenAPI 3** (`openapi.yaml`) и держать в репозитории
  бэкенда. Из него сгенерируем типы для приложения.
- Тестовый сервер (staging) с тестовыми данными, отдельный от боевого.
- На staging нужен тестовый пользователь (см. `01-auth.md`) — он нужен и
  для проверки приложения в App Store и Google Play.
